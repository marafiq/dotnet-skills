Integrations/Inbound/New source

New inbound source

Register a partner that will POST to ALIS. The system generates a stable URL; you configure how we verify them and where to dispatch verified events.

Draft
01

Provider template

Start from a known partner — we know their verification scheme, header conventions, and idempotency rule. Or configure custom.

02

Your receive URL

This is the URL you give the partner. The path is unique to this tenant + source so traffic stays isolated.

POSThttps://hooks.alis.health/brookside/in/stripe-prod
Configure this URL in your provider's webhook settings. Stable for the lifetime of this source.
Stable for the lifetime of this source. Cannot be changed once activated.
Required · lowercase letters, digits, hyphens; must be unique within tenant
Required · 3–80 characters
03

How does the partner prove identity?

Verification scheme — chosen by the partner, configured here. Custom partners can pick from any category.

04

Idempotency key

Where does the partner's unique-event-id live? We use it to dedupe — same key, same event, processed once.

05

Dispatch handler

After verification + dedupe, ALIS hands the event to your handler. The handler runs on the worker pool, not on the HTTP request.

After we verify and dedupe, we enqueue the event for this handler.
